# Visual sources and how to read them

An illustration should answer a question that is harder to answer from prose alone. Commands and short terminal results are text so you can select, search and compare them. Expected-output panels have a separate colour and label and no Copy button.

## Concept diagrams

The robotics feedback loop, software stack, ROS communication patterns, middleware boundaries, callback timeline, QoS comparisons, coordinate geometry and camera geometry are original course diagrams. Their captions explain what to trace or compare; they are models of a system, not screenshots of a running experiment. Technical references accompany the corresponding lesson. Original course diagrams are shared under the course's **CC BY 4.0** terms; retain the course attribution when reusing them.

### Animated introductions in lecture 01

The communication comparison and package-to-graph illustrations are original SVG artwork generated by `maintenance/tools/make-motion-visuals.mjs`. Moving dots represent messages; their timing is illustrative. Labels, directions, use cases and interface options remain readable in the static companion images. The website provides a Pause animation button, a full-size view and static alternatives; reduced-motion preferences select static images initially.

`Extra_Content.docx`, supplied by the course author, informed the added explanations and diagram subjects. Its embedded pictures were references only; none were copied into the course. The diagrams use ROS 2 terminology and node-owned parameters. They simplify action protocol exchanges into goal, acceptance, feedback and result, rather than depicting every underlying service/topic packet. The linked official ROS concept pages supply the protocol details.

## Windows launch illustration

The three-method Ubuntu launch image in lecture 00 is an **AI-generated simulation**, with explanatory callouts outside the application panels. It is not a captured Windows session; theme, icons, profile names and menu arrangement can differ on your machine. The methods themselves are supported by [Microsoft's WSL command documentation](https://learn.microsoft.com/en-us/windows/wsl/basic-commands) and [Windows Terminal profiles](https://learn.microsoft.com/en-us/windows/terminal/customize-settings/profile-general).

Use the copyable text command in the lesson when typing. Windows and Ubuntu interface marks identify the software being taught; they do not indicate endorsement.

## Selection and reuse

Retain the source attribution and license when reusing the upstream RViz screenshot. Original course diagrams use CC BY 4.0. Sources are linked next to the lesson they support.

The conceptual phone-equipment illustration retained in the course is AI generated and labelled conceptual. It is not a calibration target or an experimentally measured reconstruction. Learners should submit their own terminal logs, screenshots and measurements as evidence.

## Shared interfaces, reuse and DDS

The three framework diagrams in lecture 01 are original vector redraws of the teaching concepts in the course-author supplied references. They use the course cream, forest-green and copper palette. The reuse diagram groups software capabilities around the learner’s application. The DDS band is a logical data space, not a central broker or a physical bus; arrows show example roles rather than every topic connection. These diagrams use the course CC BY 4.0 terms.
